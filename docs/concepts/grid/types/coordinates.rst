.. _grid-unstructured:

Grids defined by coordinates
============================

Some grids are not generated by a formula: their coordinates are data.

Unstructured grids
------------------

**Unstructured grids** (``unstructured_ll``) are built from arrays of latitudes and
longitudes. Their uid is a digest of the coordinates, so the same points always have
the same uid. A ``name`` registers the grid under that name:

.. code-block:: python

    grid = Grid(latitudes=[1, 2, 3], longitudes=[4, 5, 6])
    grid.spec                      # {'type': 'unstructured_ll', 'uid': '...'}
    assert grid == Grid(uid=grid.uid)

    named = Grid(latitudes=[1, 2, 3], longitudes=[4, 5, 6], name="my-stations")
    assert named == Grid("my-stations")

Any other grid can also be turned into an unstructured grid (see
:ref:`grid-as-unstructured`).

.. _grid-orca:

ORCA grids
----------

**ORCA grids** come from the catalogue (see :ref:`grid-catalogues`), with coordinates
retrieved when they are first needed. They are the tripolar ocean grids of NEMO, in
the five staggered positions of NEMO's Arakawa C-grid: ``T``, ``U``, ``V``, ``F`` and
``W``. The extended grids (``eORCA...``) reach further south, under the Antarctic
ice shelves. Their canonical spec gives the grid's name (and its uid, when the name
does not identify it), and ``grid.catalog`` holds the rest, such as the shape and the
URL of the coordinates.

.. _grid-as-unstructured:

Any grid as an unstructured grid
--------------------------------

A grid with geographic points can be turned into an unstructured grid of the same
points, in the same order. This applies to any such grid, whatever its type: regular,
Gaussian, HEALPix, rotated or projected, or ORCA. The result is an ordinary grid of
type ``unstructured_ll``. It can be used wherever a grid is expected, by any code
that needs only the points, without knowing the structure of the original grid.

.. code-block:: python

    from earthkit.geo.grids import Grid

    grid = Grid("O32")
    points = grid.to_unstructured_ll()

    points.type                                       # 'unstructured_ll'
    points.shape                                      # (5248,), as grid.size()
    points.spec                                       # {'type': 'unstructured_ll', 'uid': '...'}
    assert points.to_latlons() == grid.to_latlons()   # the same points, in the same order

The conversion gives the same grid as building one from the coordinates:

.. code-block:: python

    lat, lon = grid.to_latlons()
    assert Grid(latitudes=lat, longitudes=lon) == points

Identity
~~~~~~~~

The unstructured grid is a different grid from the original (``points != grid``). It
has its own spec and its own uid, because it no longer carries the structure: no grid
name such as ``O32``, no area or rotation describing the points, and no other order
to renumber them into. Its uid is a digest of the coordinates. The same points
therefore always give the same uid, in any process: building the grid from the same
coordinates elsewhere reproduces it exactly. Within a process, ``Grid(uid=points.uid)``
returns it.

Names
~~~~~

A name registers the unstructured grid under that name, without changing its uid. The
name must not already belong to another grid:

.. code-block:: python

    points = grid.to_unstructured_ll("o32-points")

    points.spec                         # {'grid': 'o32-points'}
    assert Grid("o32-points") == points

Subsets
~~~~~~~

``grid.cropped_unstructured_ll(area)`` gives the points of a grid inside an area as
an unstructured grid, in the grid's order. ``grid.cropped(area)`` does the same
whenever the cropped grid cannot keep the original type, for example for a polygon
(see :ref:`grid-area`):

.. code-block:: python

    from eckit.geo import Area

    europe = grid.cropped_unstructured_ll(Area(area=[72, -25, 25, 45]))

Using it as a grid
~~~~~~~~~~~~~~~~~~

An unstructured grid offers everything that depends on the points alone:

- geographic and geocentric coordinates (``to_latlons()``, ``to_xyz()``,
  ``to_points()``);

- cropping by any area, with unstructured results;

- nearest-neighbour searches (``search()``);

- its spec and uid, to exchange and identify the points;

- regridding, as an input or an output grid, with the spec
  ``{latitudes: [...], longitudes: [...]}``.

earthkit-geo relies on this when it regrids data whose grid has no spec: it falls
back to treating the input as unstructured. Interpolation then works from the points
alone, without a structure to exploit, so nearest-neighbour interpolation is
recommended (see :ref:`regridding-unstructured`).
